Как устроен канал «Бионика и реабилитация»

Автономный конвейер новостей индустрии протезирования и реабилитации: сбор через LLM (ChatGPT API, запасной — Anthropic; выбор в scripts/llm.py), очередь в GitHub, публикация в Telegram по расписанию, бот управления, монитор и Атлас отрасли (он же Telegram Mini App). Своего сервера нет: всё работает в GitHub Actions, GitHub Pages и n8n.

Цифры (число компаний, новостей, историй, ширина сбора) здесь намеренно не приводятся — актуальные значения на вкладках «Монитор» и «Атлас отрасли».

Узлы системы

Сбор

Сборщик harvest

Ищет события по компаниям из companies.md и по темам отрасли, классифицирует и пишет в очередь.

  • LLM через scripts/llm.py: OpenAI gpt-5-mini + встроенный web_search (с 08.11.2026; запасной — Anthropic Haiku 4.5, переменная LLM_PROVIDER)
  • «Ширина» 1–7: компании → отрасль → выставки → лица → наука/клиника → регуляторика/рынок РФ → смежные
  • Авто-режим по буферу: меньше 15 новых — шире, больше 40 — уже
  • Текст без кириллицы или с иероглифами переводится на русский; служебная разметка вырезается
  • Не берёт хирургических роботов (Mako, ROSA, CUVIS, VELYS, da Vinci, CMR): сегмент не отслеживается
Данные

Очередь и справочники

Единственный источник правды — репозиторий.

  • news_queue.jsonl — новости, статусы new / posted / blocked
  • facts.jsonl — серии «История компании» (3–8 постов на компанию)
  • companies.md — отслеживаемые компании (мир + РФ); формат фиксирован, его читает сборщик
  • promo.json — повторяющийся пост про Атлас: текст, кнопка, даты
  • harvest_state.json — текущая ширина сбора и история
  • dashboard/multiples.json — рыночные данные публичных компаний
Защита

Дедуп

Одно событие из разных СМИ не должно выйти дважды.

  • Ступень 1 — правила при записи в очередь (append_news.py)
  • Ступень 2 — те же правила по всей очереди перед публикацией (dedup_scan.py)
  • Ступень 3 — смысловая проверка LLM против постов за 45 дней (llm_dedup.py), только для спорных
  • Подробно — раздел «Защита от дублей» ниже
Публикация

Публикатор

publish.py --auto держит дневную норму. Пост — HTML с эмодзи, хэштегами и строкой «дата · источник».

  • Новости: ceil(new/10) в день, равномерно 09:23–19:23 МСК, свежие вперёд
  • Истории: 2 в день, 11:23 и 16:23 МСК, по списку приоритета компаний
  • Промо Атласа: по датам из promo.json, ~13:23 МСК, с кнопкой «Открыть Атлас»
  • Ручные публикации помечаются и не съедают плановые слоты
Внешнее

n8n

Точный будильник вместо ненадёжного GitHub-cron и бот управления.

  • Каждые 30 минут (:23 и :53, 9–19 МСК) запускает publish.yml через GitHub API
  • Бот @MA_Prosthetics_bot: компании, новости (публикация, блок), ширина сбора, истории
  • Бот отвечает только администратору; остальным — ссылка на Атлас и канал
Витрины

Монитор, Атлас, Мультипликаторы, Архитектура

build_balance.py собирает balance.json; dashboard.yml публикует страницы в публичный репозиторий на GitHub Pages.

  • Обновление сразу при правке страниц или данных и по расписанию раз в 2 часа
  • Монитор — баланс очереди, ширина сбора, истории
  • Атлас — каталог компаний с фильтрами, карта «продукты × география», истории (вышедшие и «скоро в канале»), новости со ссылками на источники
  • Атлас работает и как Telegram Mini App: тема Telegram, кнопка «Назад», ссылки через клиент
  • Мультипликаторы — отдельная вкладка дашборда (multiples.html): EV/выручка, EV/EBITDA LTM, MCap публичных компаний; multiples.json обновляет multiples.yml 1-го числа месяца из Yahoo Finance

Защита от дублей: сначала формальные признаки, потом LLM

Одно событие пересказывают десятки СМИ разными словами. Дешёвые правила отсекают очевидные повторы, а модель (LLM) смотрит только спорные случаи — так дедуп почти ничего не стоит.

СтупеньКогда и гдеЧто проверяетИтог
1. ПравилаПри записи в очередь, append_news.py Та же ссылка. Та же компания и похожий заголовок (с учётом дат). Общее латинское имя (продукт, купленная компания) ± 3 дня. Сделка двух компаний: обе названы в обоих заголовках ± 3 дня. Одна сумма сделки («10,5 млн», «$10.5M») у той же компании или названной в тексте ± 3 дня. Дубль в очередь не попадает. Бесплатно.
2. ПравилаПеред каждой публикацией, шаг «Dedup queue», dedup_scan.py --apply Те же правила по всей очереди: ищет группы записей об одном событии. В группе остаётся одна запись, лишние → blocked. Бесплатно.
3. LLMВ момент отправки поста, llm_dedup.py из publish.py Сначала фильтр без API: есть ли в канале за 45 дней посты о той же компании (или она названа в тексте, или общее имя в заголовке). Нет — пост выходит без запроса. Есть — LLM сравнивает новость с этими постами (до 25) по смыслу. Вердикт модели (ниже). Запрос — доли цента; нужен примерно для 60% новостей.

Вердикты ступени 3

  1. Новое событие — обычный пост. Следующий раунд, другой продукт, выставка в другом городе — это новое.
  2. Повтор — то же конкретное событие без важных новых фактов. Не публикуется: status=blocked, dup_of = id исходного поста; место занимает следующая новость.
  3. Новые детали — то же событие, но есть важное, чего не было ни в одном посте: сумма или итог раунда, новые участники, регуляторное решение, сроки, цена, результаты испытаний. Выходит короткий пост «🔄 К новости про …: новые детали» ответом на исходный пост.

Надёжность и контроль

  1. Нет ключа или сбой API — пост выходит как раньше, ступени 1–2 уже отработали.
  2. Сомнение «новое или повтор» модель решает в пользу публикации; «детали или повтор» — в пользу повтора.
  3. Решение и причина пишутся в лог запуска publish.yml и в запись очереди (dedup).
  4. Ошибочно заблокированную новость можно выпустить вручную по id (ручная публикация ступень 3 не проходит).
  5. Бэктест: workflow dedup-backtest проигрывает всю историю канала, отчёт — reports/dedup_backtest.md. Запускается сам при правке llm_dedup.py.

Модель — как в сборщике: gpt-5-mini (OpenAI), запасная — claude-haiku-4-5. Пример: сделка Ottobock → Blue Arbor вышла 4 раза; со ступенью 3 второй и третий пост стали бы «новыми деталями» ($10,5 млн, итог раунда $15,5 млн), четвёртый — отсеян.

Типовые действия

  1. Опубликовать или снять новость — бот или publish.yml (id / block).
  2. Проверить пропущенную ссылку — check.yml (add, publish).
  3. Сменить ширину сбора — бот, «Широта сбора».
  4. Добавить компанию — скилл ma-add-company в Claude Code.
  5. Поменять промо-пост или даты — promo.json.
